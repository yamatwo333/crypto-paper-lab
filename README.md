# crypto-paper-lab

仮想10,000円で、ETH単独と複数銘柄の固定ルールを比較する前向き検証です。
実資金、実注文、入出金、取引所へのログイン、有料AI APIは使いません。

## 比較する方式

各方式に独立した仮想10,000円を用意し、「同じ予算ならどちらがどうなったか」を比べます。
複数銘柄方式の銘柄ごとに10,000円を追加する意味ではありません。

| 方式 | 対象と資金配分 |
| --- | --- |
| 新規ETH比較口座（準備中） | ETH/JPY。購入時資産の25%。通常・高コスト・日次基準を記録 |
| 複数銘柄比較口座 | BTC/ETH/XRP/SOL。共通現金、最大2銘柄、各購入時12.5%、購入後の保有比率合計25%以内 |

利益も損失も次回購入額に反映します。最小購入単位に届かない銘柄は見送ります。
レバレッジ・空売り・ナンピンは行いません。90日間はルールを固定し、180日かつ20往復以上を評価の最低目安とします。
評価後も実資金へ自動移行しません。過去の未確認区間に注文を後付けしません。

過去の比較では、複数銘柄方式が有利だった期間と不利だった期間がありました。
特に2025年2月〜2026年10月17日の検証では、通常コストでETH単独+15.39%、複数銘柄−8.84%でした。
この結果は期間合計の事後検証で、将来の利益を示すものではありません。
複数銘柄方式は有利だと決めつけず、比較仮説として扱います。

## リポジトリ構成

- `work/paper-trading/`：元のETHの固定プログラムとテスト。
- `comparison/`：比較用ETH・複数銘柄の固定プログラムとテスト。
- `frozen_source_sha256.json`：変更を検出するための固定ソース一覧。
- `scripts/probe.py`：相場取得と保存の限定的な結合テスト。帳簿にはアクセスしません。
- `scripts/ledger_store.py`：SQLiteの状態・履歴を一文字も変えずに保存・復元する移行用処理。小さな履歴ファイルに分けて保存します。相場取得・初期化・売買は行いません。
- `scripts/cloud_runner.py`：別実験の開始確認と、復元・固定プログラムの実行・保存をつなぐ処理。通常の実行から初期化はできません。
- `control.json`：新規開始への同意と実験IDを記録。開始が確定保存されると `phase` が `running` になります。
- `scripts/launch_gate.py`：承認と予約検証の成功を読み取り専用で確認。未達なら待機します。
- `validation/history.json`：検証の実行結果。作成された場合は公開されます。

## GitHub上の初期検証

標準Linuxランナーを使い、実行結果はこのリポジトリへ保存します。
Actionsの成果物・永続キャッシュ・大型ランナー・外部有料APIは使いません。

1. `Frozen strategy tests` がソース同一性とオフラインの売買・会計テストを確認します。
2. `Public data and persistence validation` が4銘柄の取引状態・板・当日15分足を公開APIから取得します。
3. 別プロセスで保存結果を検証し、次の予約実行で前回の記録を読み直します。
4. 異なる15分区間で予約実行が2回成功したら、検証予約を自動停止します。
5. 別実験への同意を記録した場合に限り、売買用ワークフローが別実験の開始条件を確認して進みます。旧帳簿を初期化し直しません。

最初の手動・コード更新時の確認は予約成功2回に数えません。最大試行数は5回です。
明示的な通信拒否・記録不整合・実行失敗が起きた場合も検証予約を停止し、別経路で再試行しません。
予約を止めるにはActions一覧で該当ワークフローをDisableします。
予定時刻は毎時7・22・37・52分（UTC、日本時間でも分は同じ）ですが、遅延・欠落はあり得ます。

この確認は接続と保存の検証です。売買プログラム全体・本番帳簿の移行成功とは区別します。

## 新しい比較実験の開始前に残っていること

予約検証2回の成功、65日分の事前データ取得を含む全体の実行、
初期帳簿の保存・別実行での再読み込み、その後の実行確認が必要です。
毎時12・27・42・57分の予約と検証完了時の起動を設定していますが、条件成立前は読み取り確認で終了します。
初期帳簿を保存できたら別のGitHub実行を起動し、Gitに保存された原本から復元して最初の観測を行います。
旧帳簿を初期化し直しません。新しい開始日時から比較し、旧成績と合算しません。

帳簿の保存・復元は、両エンジンのテスト用の買い・売り履歴で全レコード一致と元のverifyの成功を確認しています。
このテスト用帳簿は公開・運用していません。本番帳簿の受領と検証が済んだことを意味しません。
